# DRAMCap video captioning with candidate reranking

The selected configuration reaches **77.29 CIDEr** on the 497-video MSR-VTT validation split. It extends the DRAMCap video captioner with candidates from the A, C, and D ablations.

| Validation configuration | CIDEr |
| --- | ---: |
| B, epoch 7, direct generation | 74.70 |
| B, epoch 7, reranking its own candidates | 77.15 |
| **B plus A/C/D candidates, reranked** | **77.29** |

[Exact scores and output checksums](results.json) record the archived evaluation. Each video contributes one final caption scored against 20 human references with the COCO caption evaluation toolkit. The configuration was selected on validation. Evaluation on the 2,990-video test split remains pending.

## Candidate scoring

1. Start with B's beam-3 caption. Add up to five distinct captions generated by the same B checkpoint with beam size 5, followed by the saved A, C, and D predictions.
2. Retrieve the eight nearest training videos by cosine similarity of cached visual features. Score each candidate against their training captions with a CIDEr-style similarity whose document frequencies come from the training captions.
3. Add the gain in B's mean token log-likelihood to 0.32 times the gain in retrieval score, both relative to the beam-3 caption. The candidate must improve the retrieval score by more than 0.05, lose at most 0.20 in mean token log-likelihood, and improve the combined score by more than 0.025. Keep the beam-3 caption if no candidate meets those conditions.

Candidate selection uses model scores and captions from the 6,513 training videos. Validation references are used to verify the evaluation split, compute metrics, and compare the complete configurations.

## Reproduce the archived run

Use Python 3.10 or newer, a CUDA GPU with BF16 support, and the DRAMCap dependencies from the repository root. Install the evaluation dependency with `pip install pycocoevalcap` and put a Java runtime on `PATH` for PTB tokenization and METEOR.

The command expects the original split files, feature caches, checkpoints, and saved candidate predictions. Prepare the model weights and experiment artifacts separately. The repository includes the code and the evaluation summary.

| Input | Required artifact |
| --- | --- |
| Split directory | Original MSR-VTT `train.jsonl` and `val.jsonl` |
| Feature directories | Matched EVA visual, spatial, and relation-event caches, each with provenance metadata |
| Model weights | Image-language checkpoint (`stage2_final.pt`), Vicuna-7B-v1.5 directory, and B epoch 7 checkpoint |
| Candidate directory | The four validation prediction files and their accompanying metric JSON files listed below |

Use the original archive layout for the B checkpoint and candidates. Each `_predictions.jsonl` has a matching `_metrics.json` that records the prediction and reference checksums.

```text
CAPTION_ARCHIVE/
├── A_validation/epoch_008_predictions.jsonl
├── B/training/epoch_007.pt
├── B/validation/epoch_007_predictions.jsonl
├── C/validation/epoch_007_predictions.jsonl
└── D/validation/epoch_002_predictions.jsonl
```

From the DRAMCap repository root, with the paths set to the matching artifacts:

```bash
export PYTHONPATH="$PWD"
python experiments/msrvtt_b_acd/ensemble_msrvtt_b.py \
  --root "$ASSET_ROOT" \
  --run "$CAPTION_ARCHIVE" --original-abcd "$CAPTION_ARCHIVE" \
  --split-root "$SPLITS" \
  --feature-cache "$EVA_FEATURES" --spatial-cache "$SPATIAL_FEATURES" \
  --event-cache "$EVENT_FEATURES" \
  --image-checkpoint "$IMAGE_CHECKPOINT" --decoder "$VICUNA_DIR" \
  --output "$OUTPUT_DIR" --verify-archive
```

Use a fresh output directory. The final artifacts are `B_plus_ACD_predictions.jsonl` and `B_plus_ACD_metrics.json`. The `B_plus` outputs record the B-only reranking control. `--verify-archive` checks the hashes of both prediction files against the archived run.
